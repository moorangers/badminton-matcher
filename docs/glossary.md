# Glossary

คำศัพท์ที่ใช้ในโค้ด/เอกสาร/บทสนทนาเกี่ยวกับโปรเจกต์นี้ เรียงเป็น 2 กลุ่ม: **มีอยู่แล้วในโค้ดปัจจุบัน** กับ **เสนอใหม่ (ยังไม่ implement)**

## มีอยู่แล้วในโค้ดปัจจุบัน

| คำ | ความหมาย |
| --- | --- |
| **Player** | ผู้เล่น 1 คนในรายการ มี `id`, `name`, `matches` (จำนวนแมตช์ที่เล่นจบไปแล้วสะสม) — ดู [PlayerList.tsx](../src/components/PlayerList.tsx) |
| **Match** | 1 คู่แข่งขันบน 1 คอร์ด มี `court`, `mode`, `teamA`, `teamB`, `status` — ดู [MatchBoard.tsx](../src/components/MatchBoard.tsx) |
| **Mode** | รูปแบบการเล่น: `singles` (1v1, 2 คน/แมตช์) หรือ `doubles` (2v2, 4 คน/แมตช์) |
| **Court** | คอร์ดแบดมินตัน 1 สนาม ระบุด้วยเลข 1-3 (`MAX_COURTS`) |
| **Match Status** | สถานะของแมตช์: `ready` (พร้อมเริ่ม) → `playing` (กำลังเล่น) → `done` (จบแล้ว) |
| **Session (ปัจจุบัน)** | ไม่มีแนวคิด session แยกจริง ๆ ในโค้ดตอนนี้ — ทั้งแอปคือ 1 session ต่อ 1 เบราว์เซอร์ตลอดไปจนกว่าจะกด "ล้างทั้งหมด" |
| **Next Plan / Plan Draft** | แผนที่จะใช้ตอนเติมคู่ถัดไป (mode + court ids) แก้ได้ระหว่างกำลังเล่นอยู่โดยไม่กระทบแมตช์ที่กำลังเล่น ผ่านปุ่ม "ปรับรอบถัดไป" |
| **Resting (พักอยู่)** | ผู้เล่นที่ไม่ได้อยู่ใน active match ใด ๆ ณ ขณะนั้น |
| **Recently Played (ในโค้ด: `recentlyPlayedIds`)** | ผู้เล่นที่กำลังอยู่ใน active match ของคอร์ดอื่น ณ เวลาที่จัดคิว — **ไม่ใช่** "เพิ่งเล่นจบรอบที่แล้ว" ตามที่ชื่ออาจสื่อ (จุดนี้เป็นข้อจำกัดของ logic เดิม ดู [matching-algorithm.md](./matching-algorithm.md)) |
| **Tier (จำนวนแมตช์)** | การจัดกลุ่มผู้เล่นตาม `player.matches` เท่ากัน ใช้เป็นลำดับความสำคัญหลักในการสุ่มคิว |
| **Substitute (เปลี่ยนตัว)** | การสลับผู้เล่น 1 คนออกจากแมตช์ที่กำลังเล่น แล้วสุ่มคนพักมาแทน โดยผู้เล่นเดิมไปพัก (ไม่ถูกลบออกจากระบบ) |
| **Undo Snapshot** | การจับ state ทั้งหมดไว้ก่อนกด "จบแมตช์" หรือ "เปลี่ยนแผนรอบถัดไป" เพื่อย้อนกลับได้ (เก็บสูงสุด 5 ครั้งล่าสุด) |

## เสนอใหม่ (ยังไม่ implement — จะใช้ตรงกันในเอกสารชุดนี้)

| คำ | ความหมาย |
| --- | --- |
| **Club** | หน่วยชมรม/กลุ่มตีแบด 1 กลุ่ม (สำหรับรองรับ multi-tenant ในอนาคต) |
| **Booking / Court Session** | ช่วงเวลาที่คอร์ดหนึ่งถูกจองไว้ (มี `startTime`, `endTime`) — ที่มาของฟีเจอร์ "รวมคอร์ด" |
| **Court Merge** | เมื่อคอร์ดที่จองเวลาสั้นกว่าหมดเวลาก่อน ให้ยุบผู้เล่นจากคอร์ดนั้นไปรวมกับคอร์ดที่ยังเหลือเวลา แทนที่จะปล่อยให้คนกลุ่มนั้นไม่มีที่เล่นต่อ |
| **Check-in (ลงทะเบียน)** | ขั้นที่ 1 — ผู้เล่นแจ้งชื่อว่าจะมาเล่นวันนี้ (ล่วงหน้า หรือถึงหน้างาน) |
| **Check-in (ยืนยันหน้าคอร์ด)** | ขั้นที่ 2 — ผู้เล่นที่ลงทะเบียนไว้แล้ว ต้องกดยืนยันอีกครั้งว่า "มาถึงคอร์ดแล้ว พร้อมเข้าคิวสุ่ม" ก่อนถึงจะถูกเอาเข้า pool สุ่มจริง |
| **Self Check-in (QR)** | คนที่ไม่ได้ลงทะเบียนล่วงหน้า มา scan QR ที่คอร์ด กรอกชื่อ แล้วเข้าคิวสุ่มได้เลย |
| **Partner History** | สถิติว่าผู้เล่น 2 คนเคยจับคู่เป็นทีมเดียวกันมาแล้วกี่ครั้ง ใช้เป็น penalty score กันไม่ให้จับคู่ซ้ำเดิมถี่เกินไป |
| **Wait Time Fairness** | การให้น้ำหนักลำดับคิวตามเวลาที่ผู้เล่นรอ (`queuedAt`) ไม่ใช่แค่จำนวนแมตช์ที่เล่นไปแล้ว — แก้ปัญหาคนมาก่อนแต่ไม่ได้ priority มากกว่าคนมาใหม่ที่ matches เท่ากัน |
| **Webboard / Post Report** | กระดานโพสต์รายงานประจำวันของชมรม (เช่น วันนี้มากี่คน พร้อมรูปถ่าย) |
| **Tournament Mode** | โหมดจัดการแข่งขันแบบมีสายการแข่ง (bracket) สำหรับ singles/doubles ใช้ในงานกีฬาสี ต่างจาก casual matching ที่ใช้ทุกวัน |
| **Live Scoreboard** | จอแสดงคะแนนสดของแมตช์ที่กำลังแข่ง อัปเดตแบบ real-time ให้คนดูเห็นโดยไม่ต้อง refresh |
