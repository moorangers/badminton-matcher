# Project Context

## นี่คือโปรเจกต์อะไร

**Badminton Matcher** — เว็บแอปช่วยจัดคู่ผู้เล่นแบดมินตันหน้างานแบบ Singles (1v1) หรือ Doubles (2v2) ให้กับกลุ่ม/ชมรมตีแบดที่เล่นแบบ walk-in ไม่ใช่ทัวร์นาเมนต์ทางการ เป้าหมายคือ "จัดคู่ให้แฟร์ ไม่ต้องมีคนนั่งจดสถิติเอง"

Tagline ในแอป: *Fair · Fast · Fun*

## แก้ปัญหาอะไร

เวลาคนมาเล่นแบดกันเป็นกลุ่มใหญ่ (10-30+ คน) กับคอร์ดจำนวนจำกัด (1-3 คอร์ด) จะมีปัญหาซ้ำ ๆ:

- จำไม่ได้ว่าใครเล่นไปกี่รอบแล้ว ใครควรได้เล่นก่อน
- คนบางคนได้เล่นบ่อยกว่าคนอื่นเพราะจัดคู่มือ/สุ่มแบบไม่มีระบบ
- ต้องมีคนคอยจดชื่อคู่ถัดไปตลอดเวลา

แอปนี้ automate เรื่องนี้ให้: เพิ่มชื่อผู้เล่น → กดจับคู่ → ระบบสุ่มคู่ตามรอบ (ให้ความสำคัญคนที่เล่นน้อยกว่าก่อน) → จบแมตช์แล้วเลื่อนคิวถัดไปให้อัตโนมัติ

## ผู้ใช้เป้าหมาย

กลุ่ม/ชมรมตีแบดแบบสังสรรค์ (ไม่ใช่ทัวร์นาเมนต์แข่งขันจริงจัง) — ตอนนี้เป็นภาษาไทยเป็นหลัก (UI, toast message ทั้งหมดเป็นภาษาไทย) บ่งชี้ว่า target user คือกลุ่มคนไทย

## สถานะปัจจุบัน (ณ 2026-09-06, v0.4.2)

- เป็น **client-only web app**: Next.js (App Router) + React + TypeScript + Tailwind ไม่มี backend, ไม่มี database, ไม่มี auth
- state ทั้งหมด (ผู้เล่น, แมตช์, สถิติ) เก็บใน `localStorage` ของเบราว์เซอร์เครื่องเดียว — ปิดแอปแล้วเปิดใหม่ข้อมูลไม่หาย แต่ **คนละเครื่องเห็นข้อมูลคนละชุด** เพราะไม่มีการ sync
- ใช้งานจริงได้แล้วสำหรับ 1 คนถือมือถือ/แท็บเล็ตเครื่องเดียวคุมทั้งกลุ่ม (เช่น แอดมินชมรมยืนหน้าคอร์ดคอยกดจับคู่/จบแมตช์)
- โค้ดหลักของ business logic ทั้งหมดกระจุกอยู่ที่ [src/features/home/home-page.tsx](../src/features/home/home-page.tsx) (ไฟล์เดียว ~1500 บรรทัด ถือ state ทั้งหมดของแอป)

## ทิศทางที่กำลังจะไป

กำลังวางแผน refactor ครั้งใหญ่เพื่อรองรับ:

1. ย้ายจาก localStorage → MongoDB (multi-device)
2. ปรับ logic จับคู่ให้แฟร์กว่าเดิม (partner-history + wait-time)
3. ระบบเช็คอิน 2 ขั้น (ลงทะเบียนล่วงหน้า + เช็คอินหน้าคอร์ด) และ self check-in ผ่าน QR
4. ฟีเจอร์ "รวมคอร์ด" เมื่อคอร์ดที่จองเวลาสั้นกว่าหมดเวลาก่อน
5. Webboard สำหรับโพสต์รายงานประจำวัน (พร้อมรูปภาพ)
6. Tournament mode (เดี่ยว/คู่) สำหรับงานกีฬาสี
7. ระบบนับคะแนน + live scoreboard ขึ้นจอ
